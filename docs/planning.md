# FORGE 企画・設計ドキュメント（Phase 0〜2 記録）

`sakuyalabs_portfolio_plan.md` の「③ジム｜LP・コンバージョン」案件を、実装前に定義した内容の記録。

## Phase 0｜要件定義・ペルソナ設計

### 架空クライアント
- パーソナルジム「FORGE」（無料体験からの入会LTV最大化モデル）

### エンドユーザーペルソナ
- 30代男性。過去にダイエット・ジム通いで挫折した経験がある。
- 「今度こそ変われるのか」に懐疑的。通いやすさより「本当に結果が出るか」の証拠を求めている。
- LPは縦一本道、離脱させない設計にする（企画書③の方針）。

### ゴール（CV地点）
- 無料体験申込フォームの送信

### 成功指標（KPI）
1. 無料体験申込フォームのコンバージョン率（フォーム到達→送信）
2. 各セクションの通過率（特にFAQ→最終CTAの到達率。離脱ポイントの特定）

## Phase 1｜情報設計（IA）

### LP構成（1ページ・縦一本道、ナビゲーションメニューは持たない）
| # | セクション | このセクションの仕事 |
|---|---|---|
| 1 | Hero | ビフォーアフター訴求＋無料体験CTAをファーストビューで完結させる |
| 2 | Empathy（悩み共感） | 「こんな経験ありませんか」をチェックリスト形式で自分ごと化させる |
| 3 | Difference（差別化） | 他ジムとの違いを比較表で明示し、懐疑を崩す |
| 4 | Trainers（トレーナー紹介） | 顔と実績で信頼を担保する |
| 5 | Results（実績） | ビフォーアフター実例＋数字（継続率・平均減量値）のカウントアップで証拠を示す |
| 6 | Pricing（料金） | あえてシンプルな1プランのみ。比較検討による離脱を防ぐ |
| 7 | Voice（お客様の声） | 同じ悩みを持っていた人の声で自分ごと化を後押しする |
| 8 | FAQ | 申込前の不安（続けられるか、体験だけで勧誘されないか等）を先回りで解消する |
| 9 | FinalCTA | 無料体験申込フォーム（氏名・電話・希望日時の最小フィールド） |

### 導線設計
- LPの鉄則として、Hero以降の全セクション末尾に「無料体験に申し込む」CTAを反復配置し、どのセクションで気持ちが固まっても離脱前に申込導線へ入れるようにする。
- ページ内アンカーナビゲーションは持たない（①NAGI・②MARUMIのような複数ページ的な回遊ではなく、上から下へ一直線に読ませるLPの型）。

## Phase 2｜デザインシステム定義

- トンマナ：本気／伴走／確かな結果
- カラーパレット：Primary（鉄黒）`#141414` ／ Secondary（クリーンホワイト）`#F5F4F1` ／ Accent（鍛造の炎）`#FF4A26`
- タイポグラフィ：見出し欧文 Anton（極太コンデンス、インパクト重視）、見出し和文 M PLUS 1p Black、本文 Noto Sans JP
- 余白の基準：8pxグリッド／セクション間64px（①NAGI・②MARUMIよりさらにタイトに、LPらしいテンポの速さを出す）
- コンポーネント方針：角丸は最小限（4px程度）、ボタンは大きく・太く・押しやすく。ホバーは彩度アップ／わずかな拡大。アニメーションは間を置かず素早く立ち上がる（①NAGIの「間」、②MARUMIの「活気」よりさらに前のめりなテンポ）
- 数字カウントアップ演出：Intersection Observer＋Framer Motionでスクロール連動（企画書③の技術ポイント）

## ビジュアル素材の方針
- ①②と同じ方針：実写真は使用せず、CSS/SVGの抽象ビジュアル（鉄の質感、炎のグラデーション、筋繊維を思わせる線）で表現する。

## NAGI・MARUMIとの差別化ポイント（意思決定ログ）
- **フォーム実装の焦点を変える**：①NAGIは複雑な空き枠予約UI、②MARUMIは情報設計・導線分岐が証明軸だった。③FORGEは「LPライティング×CVR設計」が証明軸のため、フォーム自体は氏名・電話・希望日時のみの最小構成に留め、その代わりにセクション設計・コピーライティング・反復CTA配置・数字カウントアップ演出に実装の重心を置く。
- **ナビゲーションを持たない**：①②が「情報を探し回らせない複数セクションのサイト」なのに対し、③は「上から下へ一直線に読ませて説得するLP」。あえてヘッダーナビ・アンカーメニューを実装しない。
- **配色設計時点でコントラスト比を検証する**：②MARUMI Phase 5で、明るい背景に置いたアクセント色（ember）がWCAG AAのコントラスト比未達だった反省を踏まえ、FORGEでは暗背景(`#141414`)専用のaccent（`#FF4A26`、白文字との相性を優先）と、明背景(`#F5F4F1`)専用に暗くしたaccent variantを最初から分けて設計する。
